# อัลกอริทึมที่ 1 : Recursive Algorithm

## แนวคิด

ใช้อัลกอริทึมแบบเวียนเกิด (Recursion) โดยนำตัวอักษรตัวสุดท้ายของสตริงมาต่อกับผลลัพธ์ของการเรียกเมธอดกับสตริงที่เหลือ

## Pseudocode

```
ReverseRecursive(s)

ถ้าความยาวของ s <= 1
    คืนค่า s

คืนค่า
ตัวอักษรตัวสุดท้ายของ s
+
ReverseRecursive(สตริงที่เหลือ)
```

### ตัวอย่างผลลัพธ์

Input

```
hello
```

Output

```
olleh
```
### Time Complexity

```
O(n²)
```

### Space Complexity

```
O(n)
```

### ข้อดี

- โค้ดสั้น
- เข้าใจหลักการ Recursion ได้ง่าย
- เหมาะสำหรับการศึกษา

### ข้อจำกัด

- ใช้หน่วยความจำมาก
- ทำงานช้ากว่าเมื่อข้อมูลมีขนาดใหญ่
- อาจเกิด StackOverflowError

# การเปรียบเทียบจำนวนครั้งที่ประมวลผลตัวอักษร

| จำนวนตัวอักษร | Recursive | Iterative |
|---------------|----------|-----------|
| 10 | 10 ครั้ง | 10 ครั้ง |
| 100 | 100 ครั้ง | 100 ครั้ง |
| 1,000 | 1,000 ครั้ง | 1,000 ครั้ง |
| 10,000 | 10,000 ครั้ง | 10,000 ครั้ง |

แม้ว่าทั้งสองอัลกอริทึมจะอ่านตัวอักษรครบทุกตัว แต่ Recursive มีการสร้างสตริงใหม่ในแต่ละรอบ จึงใช้เวลามากกว่า

# ความแตกต่างระหว่าง String และ StringBuilder

## String

- ไม่สามารถแก้ไขค่าเดิมได้ (Immutable)
- ทุกครั้งที่ต่อข้อความจะสร้างอ็อบเจ็กต์ใหม่
- ทำงานช้าหากมีการต่อข้อความหลายครั้ง

ตัวอย่าง

```java
String s = "ABC";
s = s + "D";
```

---

## StringBuilder

- สามารถแก้ไขข้อความเดิมได้
- ไม่สร้างอ็อบเจ็กต์ใหม่ทุกครั้ง
- ทำงานได้รวดเร็วกว่า
- เหมาะสำหรับการต่อข้อความภายในลูป

ตัวอย่าง

```java
StringBuilder sb = new StringBuilder();

sb.append("A");
sb.append("B");
sb.append("C");
```

# สรุปการเปรียบเทียบอัลกอริทึม

| รายการ | Recursive | Iterative |
|---------|-----------|-----------|
| ใช้การเวียนเกิด | ✓ | ✗ |
| ใช้ลูป | ✗ | ✓ |
| Time Complexity | O(n²) | O(n) |
| Space Complexity | O(n) | O(n) |
| ความเร็ว | ช้ากว่า | เร็วกว่า |
| เหมาะกับข้อมูลขนาดใหญ่ | ✗ | ✓ |
| เสี่ยง Stack Overflow | ✓ | ✗ |

---

# สรุป

Recursive Algorithm เหมาะสำหรับการเรียนรู้หลักการเวียนเกิดและการแก้ปัญหาขนาดเล็ก เนื่องจากเขียนโปรแกรมได้สั้นและเข้าใจง่าย

Iterative Algorithm ที่ใช้ StringBuilder เหมาะสำหรับการใช้งานจริงมากกว่า เพราะทำงานได้รวดเร็ว ใช้หน่วยความจำอย่างมีประสิทธิภาพ และสามารถรองรับข้อมูลขนาดใหญ่ได้ดีกว่า

ดังนั้น หากต้องการประสิทธิภาพในการทำงาน ควรเลือกใช้ **Iterative Algorithm ร่วมกับ StringBuilder**

# อัลกอริทึมที่ 2 : Recursive Two-Pointer

## แนวคิด

เปรียบเทียบตัวอักษรตัวแรกและตัวสุดท้าย

หากไม่เท่ากัน

คืนค่า false ทันที

หากเท่ากัน

เรียกเมธอดซ้ำเพื่อตรวจสอบตัวอักษรคู่ถัดไป

จนกว่าจะพบตัวอักษรไม่ตรงกัน หรือซ้ายมากกว่าขวา
## Pseudocode

```
ถ้า left >= right

    return true

ถ้า s[left] != s[right]

    return false

return Recursive(left+1,right-1)
```
# การวิเคราะห์อัลกอริทึม

## กรณีเป็น Palindrome

Reverse and Compare

- ต้องสร้างข้อความย้อนกลับทั้งหมด
- ตรวจสอบครบทุกตัวอักษร

Recursive

- เปรียบเทียบจนถึงกึ่งกลางของข้อความ

## กรณีตัวอักษรคู่แรกไม่ตรงกัน

Reverse and Compare

- ยังต้องสร้างข้อความย้อนกลับทั้งหมดก่อน
- จึงค่อยเปรียบเทียบ

Recursive

- หยุดทำงานทันที
- ไม่ต้องตรวจสอบตัวอักษรที่เหลือ

# สรุป

Reverse and Compare เหมาะสำหรับผู้เริ่มต้น เนื่องจากเข้าใจง่ายและเขียนโปรแกรมได้ไม่ซับซ้อน

Recursive Two-Pointer มีประสิทธิภาพมากกว่าในกรณีที่พบว่าข้อความไม่ใช่ Palindrome ตั้งแต่ตัวอักษรคู่แรก เพราะสามารถหยุดการทำงานได้ทันทีโดยไม่ต้องตรวจสอบตัวอักษรทั้งหมด

ดังนั้น หากต้องการประสิทธิภาพในการตรวจสอบ ควรเลือกใช้ **Recursive Two-Pointer Algorithm**

เขียนโปรแกรมภาษา Java เพื่อตรวจสอบว่าสตริงภาษาอังกฤษมีจำนวนสระมากกว่าจำนวนพยัญชนะหรือไม่

# อัลกอริทึมที่ 1 : Recursive Counting

## แนวคิด

ตรวจสอบตัวอักษรทีละตัวโดยใช้การเรียกเมธอดแบบเวียนเกิด (Recursion)

ในแต่ละรอบจะตรวจสอบว่าอักขระเป็นสระหรือพยัญชนะ แล้วเพิ่มค่าตัวนับ จากนั้นเรียกตัวเองเพื่อตรวจสอบตัวอักษรถัดไป
## Pseudocode

```
RecursiveCount(s, index)

ถ้า index เท่ากับความยาวของ s

    หยุดการทำงาน


ตรวจสอบตัวอักษรตำแหน่ง index

ถ้าเป็นสระ

    เพิ่มจำนวนสระ

ถ้าเป็นพยัญชนะ

    เพิ่มจำนวนพยัญชนะ


เรียก RecursiveCount ตัวถัดไป
```

---
## Time Complexity

```
O(n)
```

เนื่องจากตรวจสอบตัวอักษรทุกตัวเพียง 1 ครั้ง

---

## Space Complexity

```
O(n)
```

เนื่องจากมีการสร้าง Recursive Call ตามจำนวนตัวอักษร

# อัลกอริทึมที่ 2 : Iterative Counting

## แนวคิด

ใช้ลูป `for` อ่านตัวอักษรทุกตำแหน่งในสตริง

หากเป็นสระให้เพิ่มตัวนับสระ

หากเป็นพยัญชนะให้เพิ่มตัวนับพยัญชนะ

---
## Pseudocode

```
สร้างตัวแปร vowel = 0
สร้างตัวแปร consonant = 0


วนลูปตรวจสอบทุกตัวอักษร


ถ้าเป็นสระ

    vowel++


ถ้าเป็นพยัญชนะ

    consonant++


คืนค่า vowel > consonant
```

---

## Time Complexity

```
O(n)
```

เนื่องจากอ่านข้อมูลครบทุกตัวอักษร

---

## Space Complexity

```
O(1)
```

เนื่องจากใช้ตัวแปรนับเพียง 2 ตัว

---
# จำนวน Recursive Calls

ถ้าสตริงมีจำนวนตัวอักษร n

จำนวนการเรียก Recursive จะเท่ากับ

```
n + 1 ครั้ง
```

ตัวอย่าง

```
education

ความยาว = 9

Recursive Calls = 10 ครั้ง
```

---

# ความเสี่ยง StackOverflowError

Recursive Algorithm มีโอกาสเกิด StackOverflowError

เมื่อข้อมูลมีขนาดใหญ่มาก เช่น

```
100,000 ตัวอักษรขึ้นไป
```

เพราะแต่ละการเรียกต้องเก็บข้อมูลไว้ใน Stack Memory

ส่วน Iterative ไม่มีปัญหานี้ เนื่องจากใช้ลูปแทน

---

# การเปรียบเทียบอัลกอริทึม

| รายการ | Recursive Counting | Iterative Counting |
|---|---|---|
| วิธีการทำงาน | ใช้ Recursion | ใช้ Loop |
| Time Complexity | O(n) | O(n) |
| Space Complexity | O(n) | O(1) |
| Recursive Calls | n+1 ครั้ง | ไม่มี |
| ความเร็ว | ช้ากว่า | เร็วกว่า |
| ใช้หน่วยความจำ | มากกว่า | น้อยกว่า |
| รองรับข้อมูลขนาดใหญ่ | ไม่เหมาะ | เหมาะ |

---

# สรุป

Recursive Counting เหมาะสำหรับการเรียนรู้แนวคิดการเวียนเกิด เนื่องจากแสดงขั้นตอนการทำงานแบบ Recursion ได้ชัดเจน

แต่ Iterative Counting เหมาะสำหรับการใช้งานจริงมากกว่า เพราะใช้หน่วยความจำต่ำกว่าและไม่เสี่ยงต่อ StackOverflowError

ดังนั้นสำหรับข้อมูลขนาดใหญ่ควรเลือกใช้

```
Iterative Counting
```

เนื่องจากมีประสิทธิภาพและใช้ทรัพยากรน้อยกว่า

# อัลกอริทึมที่ 1 : Recursive Two-Pointer

## แนวคิด

ใช้งานตัวชี้ 2 ตัว

- `left` เริ่มจากด้านซ้าย
- `right` เริ่มจากด้านขวา

การทำงาน

1. ถ้าด้านซ้ายเป็นเลขคู่ ให้เลื่อน left ไปข้างหน้า
2. ถ้าด้านขวาเป็นเลขคี่ ให้เลื่อน right ไปด้านหลัง
3. ถ้าด้านซ้ายเป็นเลขคี่ และด้านขวาเป็นเลขคู่ ให้สลับตำแหน่ง
4. เรียกเมธอดแบบเวียนเกิดกับช่วงที่เหลือ

---

## ชื่อเมธอด

```java
static void rearrangeRecursive(int[] a, int left, int right)
```

---

## Pseudocode

```
RearrangeRecursive(a,left,right)

ถ้า left >= right

    หยุด


ถ้า a[left] เป็นจำนวนคู่

    left++


ถ้า a[right] เป็นจำนวนคี่

    right--


ถ้า a[left] เป็นคี่ และ a[right] เป็นคู่

    สลับค่า


เรียก Recursive ใหม่
```

---

## Time Complexity

```
O(n)
```

---

## Space Complexity

```
O(n)
```

เนื่องจากใช้ Recursive Call Stack

# อัลกอริทึมที่ 2 : Iterative Two-Pointer

## แนวคิด

ใช้หลักการเดียวกับ Recursive Two-Pointer

แต่เปลี่ยนจากการเรียกตัวเองเป็นการใช้ลูป while

---

## ชื่อเมธอด

```java
static void rearrangeTwoPointer(int[] a)
```

---

## Pseudocode

```
กำหนด left = 0
กำหนด right = n-1


WHILE left < right


ถ้า a[left] เป็นคู่

    left++


ถ้า a[right] เป็นคี่

    right--


ถ้า left เป็นคี่ และ right เป็นคู่

    สลับค่า


ทำซ้ำจน left >= right
```

---

## Time Complexity

```
O(n)
```

---

## Space Complexity

```
O(1)
```

เนื่องจากไม่สร้างอาร์เรย์ใหม่

# อัลกอริทึมที่ 3 : Extra Array

2. วนรอบสอง นำจำนวนคี่ใส่ต่อท้าย

## ชื่อเมธอด

```java
static int[] rearrangeExtraArray(int[] a)
```

---

## Pseudocode

```

วนลูปหาเลขคู่

    เพิ่มลง Array ใหม่

    เพิ่มลง Array ใหม่


คืนค่า Array ใหม่
```

---

## Time Complexity


# ข้อที่ 5 การแบ่งอาร์เรย์ตามค่า k (Partition K)

## วัตถุประสงค์

เขียนโปรแกรมภาษา Java เพื่อจัดตำแหน่งสมาชิกในอาร์เรย์จำนวนเต็มใหม่ โดยกำหนดค่า `k`

ให้สมาชิกที่มีค่า

- น้อยกว่าหรือเท่ากับ `k` อยู่ด้านหน้า
- มากกว่า `k` อยู่ด้านหลัง

โดยไม่จำเป็นต้องเรียงลำดับภายในกลุ่ม

---
# อัลกอริทึมที่ 1 : Recursive Partition

## แนวคิด

ใช้งานตัวชี้ 2 ตำแหน่ง คือ

- `left` สำหรับตรวจสอบด้านซ้าย
- `right` สำหรับตรวจสอบด้านขวา

หลักการทำงาน

1. ถ้าค่าด้านซ้ายน้อยกว่าหรือเท่ากับ `k` ให้เลื่อน `left`
2. ถ้าค่าด้านขวามากกว่า `k` ให้เลื่อน `right`
3. ถ้าด้านซ้ายมากกว่า `k` และด้านขวาน้อยกว่าหรือเท่ากับ `k` ให้สลับค่า
4. เรียกเมธอดแบบ Recursive กับส่วนที่เหลือ

---

## ชื่อเมธอด

```java
static void partitionRecursive(int[] a, int k, int left, int right)
```

---

## Pseudocode

```
PartitionRecursive(a,k,left,right)

ถ้า left >= right

    หยุด


ถ้า a[left] <= k

    เรียกใหม่โดยเพิ่ม left


ถ้า a[right] > k

    เรียกใหม่โดยลด right


สลับ a[left] และ a[right]


เรียก Recursive ต่อ
```

---

## Time Complexity

```
O(n)
```

---

## Space Complexity

```
O(n)
```

เนื่องจากใช้ Recursive Call Stack

---

# อัลกอริทึมที่ 2 : Iterative Partition

## แนวคิด

ใช้หลักการเดียวกับ Recursive Partition แต่เปลี่ยนจากการเรียกตัวเองเป็นการใช้ลูป `while`

---

## ชื่อเมธอด

```java
static void partitionIterative(int[] a, int k)
```

---

## Pseudocode

```
กำหนด left = 0

กำหนด right = ความยาวของ array - 1


WHILE left < right


ถ้า a[left] <= k

    left เพิ่มขึ้น


ถ้า a[right] > k

    right ลดลง


ถ้าไม่ตรงเงื่อนไข

    สลับค่า


ทำซ้ำจน left >= right
```

---

## Time Complexity

```
O(n)
```

---

## Space Complexity

```
O(1)
```

เนื่องจากใช้ตัวแปรช่วยเพียงไม่กี่ตัว

---

# อัลกอริทึมที่ 3 : Sorting-Based Algorithm

## แนวคิด

ใช้วิธีเรียงลำดับอาร์เรย์ก่อน

หลังจากเรียงแล้ว

- ค่าที่น้อยกว่าหรือเท่ากับ `k` จะอยู่ด้านหน้า
- ค่าที่มากกว่า `k` จะอยู่ด้านหลัง

---

## ชื่อเมธอด

```java
static void partitionBySorting(int[] a, int k)
```

---

## Pseudocode

```
เรียงลำดับ Array


ค้นหาตำแหน่งสุดท้ายของค่าที่ <= k


แบ่งกลุ่มข้อมูล
```

---

## Time Complexity

```
O(n log n)
```

เนื่องจากมีขั้นตอน Sorting

---

## Space Complexity

```
O(1)
```

# ข้อที่ 6 การค้นหาคู่จำนวนที่มีผลรวมเท่ากับ k (Pair Sum K)

## วัตถุประสงค์

เขียนโปรแกรมภาษา Java เพื่อค้นหาสมาชิกสองตัวในอาร์เรย์ที่มีผลรวมเท่ากับค่า `k`

โดยกำหนดให้อาร์เรย์

- มีจำนวนเต็มไม่ซ้ำกัน
- เรียงจากน้อยไปมากแล้ว

# อัลกอริทึมที่ 1 : Brute Force

## แนวคิด

ตรวจสอบสมาชิกทุกคู่ที่เป็นไปได้ในอาร์เรย์

นำสมาชิกแต่ละตัวไปจับคู่กับสมาชิกตัวอื่น

ถ้าผลรวมเท่ากับ `k`

แสดงคู่ที่พบ

---

## ชื่อเมธอด

```java
static boolean findPairBruteForce(int[] a, int k)
```

---

## Pseudocode

```
FOR i = 0 ถึง n-1

    FOR j = i+1 ถึง n-1

        ถ้า a[i] + a[j] = k

            พบคู่


คืนค่า false ถ้าไม่พบ
```

---

## Time Complexity

```
O(n²)
```

เนื่องจากต้องตรวจสอบทุกคู่ของสมาชิก

---

## Space Complexity

```
O(1)
```

ใช้ตัวแปรเพิ่มเติมเพียงเล็กน้อย

---

# อัลกอริทึมที่ 2 : Recursive Two-Pointer

## แนวคิด

เนื่องจากอาร์เรย์เรียงลำดับแล้ว สามารถใช้ตัวชี้ 2 ตำแหน่ง

- `left` อยู่ด้านหน้า
- `right` อยู่ด้านหลัง

คำนวณ

```
A[left] + A[right]
```

เงื่อนไข

- ถ้าเท่ากับ `k` พบคู่
- ถ้าน้อยกว่า `k` เพิ่มค่า `left`
- ถ้ามากกว่า `k` ลดค่า `right`

จากนั้นเรียกเมธอดแบบ Recursive ต่อ

---

## ชื่อเมธอด

```java
static boolean findPairRecursive(
int[] a, int k, int left, int right)
```

---

## Pseudocode

```
ถ้า left >= right

    ไม่พบคู่


sum = a[left] + a[right]


ถ้า sum == k

    พบคู่


ถ้า sum < k

    เรียกใหม่โดยเพิ่ม left


ถ้า sum > k

    เรียกใหม่โดยลด right
```

---

## Time Complexity

```
O(n)
```

เพราะลดขอบเขตการค้นหาทีละตำแหน่ง

---

## Space Complexity

```
O(n)
```

เนื่องจากใช้ Recursive Call Stack

---

```java
static boolean findPairBinarySearch(int[] a, int k)
```

---

## Pseudocode

```
FOR ทุกสมาชิก A[i]

    target = k - A[i]

    ใช้ Binary Search หา target


ถ้าพบ

    พบคู่


คืนค่า false
```

---

## Time Complexity

```
O(n log n)
```

เนื่องจากทำ Binary Search จำนวน n ครั้ง

# เหตุผลที่ Two-Pointer ใช้ได้เมื่อ Array เรียงลำดับแล้ว

เนื่องจากสมาชิกถูกเรียงจากน้อยไปมาก

เมื่อ

```
A[left] + A[right] < k
```

สามารถเพิ่ม `left`

เพราะค่าทางซ้ายจะเพิ่มขึ้น ทำให้ผลรวมมากขึ้น


เมื่อ

```
A[left] + A[right] > k
```

สามารถลด `right`

เพราะค่าทางขวาจะลดลง ทำให้ผลรวมลดลง

จึงสามารถตัดส่วนที่ไม่จำเป็นออกได้

# วิเคราะห์ผล

## 1. ผลทดลองสอดคล้องกับ Big-O หรือไม่

สอดคล้อง เพราะเมื่อ n เพิ่มขึ้น Algorithm ที่มี Complexity สูงจะใช้เวลามากขึ้น


## 2. Algorithm ใดเร็วที่สุดเมื่อข้อมูลเล็ก

Brute Force อาจเร็ว เพราะโครงสร้างง่ายและไม่มีขั้นตอนเพิ่มเติม


## 3. Algorithm ใดเหมาะกับข้อมูลใหญ่

Two Pointer เหมาะที่สุด เพราะมี Time Complexity O(n)


## 4. Recursive มีข้อจำกัดอย่างไร

ใช้ Stack Memory มากขึ้น เมื่อข้อมูลใหญ่เกินไปอาจเกิด StackOverflowError


## 5. ทำไม Big-O เท่ากันแต่เวลาจริงต่างกัน

เพราะจำนวนคำสั่งภายใน Loop, Function Call และการใช้ Memory แตกต่างกัน


## 6. การวัดเวลาครั้งเดียวเพียงพอหรือไม่

ไม่เพียงพอ เพราะเวลาขึ้นกับ CPU และโปรแกรมอื่นที่ทำงานอยู่

จึงต้องทดลองหลายครั้งและใช้ค่าเฉลี่ย
